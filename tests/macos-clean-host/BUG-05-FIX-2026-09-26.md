# BUG-05: preserve an applied outcome when final writes fail

Install, upgrade, state edits, rollback, and resumed activation now record the
current-switch boundary before writing mutable views or the committed journal
row. A later failure identifies the generation and requires forward recovery.
JSON and JSONL add `error.recovery.generation` and `error.recovery.outcome`.
`applied` confirms the switch; `uncertain` preserves a possible switch when
activation could not confirm its final durable step. The hint rejects a blind
repeat of the original change and directs the user to repair after fixing the
write failure.

Applied operations receive a completion request when local finalization fails.
Completion reconciliation retries completion on a live handle. It never sends
cancellation for applied work. Failures before activation still permit cancellation.

This fix is local and unreleased. The [original audit](BUG-HUNT-2026-09-26.md)
records the failure. Release work remains deferred.
