# BUG-01: isolate broker disconnect cleanup

The fix binds automatic cleanup to the connection that started each operation.
A command from another connection for the same user keeps its operation,
cancellation token, and admission gates. Explicit same-user handle polling,
completion, and cancellation still work after reconnecting.

This is a local implementation and regression proof. It is not a release.
The original [bug audit](BUG-HUNT-2026-09-26.md) records the failing behavior.

## Regression checks

The new unit regression failed before the fix: the other connection's operation
became `Cancelled`. It now passes for all eight operation kinds. The tests also
check owner cleanup, admission release, and explicit same-user reconciliation.
A real Unix socket regression closes a second same-user transport and confirms
that the first connection's activation remains `Running`.

The original isolated [broker probe](evidence/2026-09-26-bug01-fix/broker-session-probe.log)
now exits 0. Both the same-user and different-user controls retain the operation
and build gate. The original failing evidence remains in the audit directory.

The VM [transcript](evidence/2026-09-26-bug01-fix/transcript.txt) records ten cases:

- Case 4 left `pkg remove fzf` at its approval prompt. Case 5 ran
  `pkg doctor --json` in another terminal and exited 0. Answering `y` in case 4
  then removed fzf successfully as generation 12.
- Case 6 confirmed removal, rolled back, and executed the restored fzf.
- Case 7 installed hello while case 8 ran doctor during package preparation.
  Both succeeded. Hello then executed successfully.
- Case 9 declined removal. It exited 75/`CANCELLED`. Case 10 confirmed that hello
  remained installed, generation 14 stayed active, and doctor remained healthy.

The VM is stopped with the test broker retained. The separate BUG-02 failure VM
was not changed.
