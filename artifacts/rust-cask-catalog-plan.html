1. Goal

Turn one pinned Homebrew Cask snapshot into native Nix packages on two systems: aarch64-darwin and x86_64-linux. No Brew. No Ruby. No token allowlists. No hosted API. No scheduler. No auto-updater. Breaking changes are allowed. There is no compatibility layer, because the product has not launched.

2. Architecture flow

Why two tools. Generation holds complex logic: variation merge, eligibility, typed plans. Rust gives an offline, unit-testable binary under the workspace lint policy. The Nix build must stay data-driven and generic, so a small build-time helper written in Python (standard library only) takes the plan as JSON and does the extraction steps. The helper is build machinery. No Python runs on the client at any time.

4. Exact contracts

One committed document: catalog.json, schema pkg-cask-catalog/2. Envelope fields: schema, generator{name,version}, input{url,revision,sha256,license}, targets (aarch64-darwin, x86_64-linux), macosBaseline:"15.7.7", and entries keyed by token. Provenance carries no field-coverage data; the coverage summary prints to the terminal and lands in the dated verification note.

Every entry carries a required token string, plus name, description, version, homepage (each string or null) and a targets map. A target record carries status (eligible or excluded), kind, reason, detail, effective version and homepage, and plan. Eligible ⇒ kind string, null reason, null detail, and a plan. Excluded ⇒ null kind, a reason code, a nullable detail, and a null plan. Every target system is present for every valid token. A token absent from entries is unknown — never eligible.

Reason codes (bounded; exactly what the generator emits)

installer-script, unsupported-artifact, unsupported-container, no-installable-artifact, missing-url, missing-checksum, minimum-os, unsupported-platform, arch-unsupported, disabled, deprecated, formula-dependency, cask-dependency-integration, unsupported-download-spec, malformed-record. There is no native-installer code.

Failure model: one bad record vs a corrupt document
  • Raw malformed record (missing field, bad path, unknown kind): isolated. That token is excluded with a reason. The catalog still generates. Search over the index returns every other row.
  • Corrupt generated index (wrong schema, broken JSON): the client rejects the whole document with an error naming the schema found and the schema supported. There is no second client-side classifier and no partial read.
  • Whole-catalog integrity (generator, fails before any output is replaced): duplicate tokens; a token that is not a usable key; pin hash mismatch; snapshot root not a nonempty JSON array; snapshot where no record carries supported_platforms. There is no "conflicting versions" check — wholesale variation replacement makes conflicts impossible — and no generator schema self-check.

OS support is collected, not inferred. The generator reads the actual target list and explicit constraints: supported_platforms membership (exact tags arm64_sequoia, x86_64_linux) and depends_on OS/arch entries. Variation keys and artifact kinds are never OS evidence.

5. Scope and deletions

In. macOS app bundles with CLI paths, completions, and manpages; pure-payload .pkg under the structural rule (build path, section 7); Linux binaries through autoPatchelf with a bounded runtime-library closure; AppImages through appimageTools.wrapType2.

Out. No dependency graph, no closure expansion, no cycle handling: records with formula or cask dependencies are excluded with recorded reasons and installs stay single-package. No fonts, no services, no drivers, no privileged installers, no formula bottles. No hosted API, no scheduler, no auto-updater.

Deleted. The brew-nix flake input; curated token lists and overrides; client CASK_SYSTEM, casks_supported_on, and the pkg-cask-support/1 decode path with its fixture. Abandoned draft scope (dependency graphs, per-package files) is removed from the plan, superseded by the binding contract.

7. Build path and the safe .pkg boundary

Generic path. fetchurl fetches the pinned URL and hash. The helper unpacks with pre-write validation: member names and symlink targets are checked before any write; duplicates and conflicts are rejected; zip/tar use stdlib extraction with realpath checks; xar/cpio go through libarchive secure extraction; 7z/DMG extract regular files only, then links are re-created after validation. Artifacts are placed, then a post-install audit resolves every output link. macOS bundles stay byte-identical: no strip, no shebang patching — signatures survive.

.pkg boundary (structural, not a token list). The build accepts only relocatable app-bundle layouts: a payload Applications directory of .app bundles, a top-level .app, or a bare Contents directory rebuilt as a bundle from its Info.plist CFBundleName. Plain files and any other shape fail the build naming the component. The build rejects Scripts, a Distribution stanza (choice-requiring installers are unsupported), nested component pkgs, plugins, and system locations (Library/System files, launchd services, kexts, privileged helpers). Essential payload is never silently dropped. Nothing runs /usr/sbin/installer or any privileged installer.

Resolved 2026-09-28. Twelve pkg records whose upstream Distribution requires choices are excluded at generation as installer-script; meta-quest-remote-desktop is excluded as unsupported-container. The final review also made malformed dependency/option/variation shapes strict, rejects duplicate artifact targets, and validates macOS constraint shapes on all targets while baseline comparison and minMacos apply only to aarch64-darwin, never Linux.

8. Client lifecycle

Search reads catalogIndex once per query (existing cache and stale rules apply) and filters locally with the declared regex crate — Rust regex grammar, documented as such; the Nixpkgs lane passes patterns to nix search unchanged. The client reads targets before any per-system data, so an untargeted system is platform-skipped without probing attributes. info and install resolve packages.<system>.<token>; excluded tokens are refused with their recorded reason; unknown tokens are refused as unknown. Installs keep the original moving reference, so native upgrade, rollback, removal, and launcher sync behave like every other package. Homebrew cleanup hooks (zap, uninstall) never run.

9. Catalog update procedure

Maintainer commands, copy and run from the repository root:

cargo run -p cask-catalog -- fetch \
  --revision 245947c0b920cbe83f4003bb7c6be737352c8314 \
  --sha256 1f19ecee6bad49e35d3f96cf295fd728db2ce8f7cdd95efdbcf250e5f4529251 \
  --pin nix/casks/catalog/input.json

cargo run -p cask-catalog -- generate \
  --pin nix/casks/catalog/input.json \
  --out-dir nix/casks/catalog

git diff --stat nix/casks/catalog/   # review, then commit pin and catalog together

Actual flags: fetch --revision --repo --sha256 --cache-dir --pin; generate --pin --input --cache-dir --out-dir (defaults shown above). Regeneration from the committed pin must be byte-identical; a diff means drift. CI runs the same check on catalog changes.
