## Contracts

Every journey runs the compiled CLI, real Nix, real local derivations, and a
disposable profile. The fixture compiles a C program that Nix uses as a builder.
The installed program prints its version when the test executes it.
The failing derivation prints a fixed diagnostic and exits with status 42.

## Test corrections

Both original hosted native jobs failed at `assert not cache_base.exists()`.
Nix can create its own cache during doctor probes. The corrected assertion checks
that pkg's cache is absent and that doctor reports it as empty.
It still checks config bytes, profile state, and registry state.

Compact failure output selects the native cause and log path. The failure
journeys use verbose mode to verify the builder's own diagnostic.
Python reports termination by SIGINT as `-2`. A handled SIGINT can return 130.
The lock journey accepts both and checks the other process and profile state.

An early fixture gave a low generation number a newer date than later history.
Nix aborted during prune on Linux and macOS. That invalid date sequence is not
the retained test. The final fixture keeps generation dates in order. It checks
recent retention first, then ages all remaining generations to check that an old
active generation survives. No Nix behavior or host protection was changed.

Nix also keeps the generation that was active at the cutoff. The expected set
includes that generation. This follows the
[Nix age-retention contract](https://nix.dev/manual/nix/2.34/command-ref/nix-env/delete-generations)
and the
[Determinate Nix 3.22.5 implementation](https://github.com/DeterminateSystems/nix-src/blob/v3.22.5/src/libstore/profiles.cc#L171-L200).

## Source-lock test isolation

The next hosted Linux Rust run failed at
`stage_and_publication_keep_the_source_lock_until_drop`.
Its immediate post-drop probe returned `WouldBlock`.
The unchanged library suite reproduced that same failure on run four in a fresh
E2B sandbox with 32 parallel test threads. The prior three runs passed.

The test shared its process with tests that fork children. Rust file locks
remain held through inherited descriptors. A Linux pipe-controlled fork check
confirmed that dropping the parent's descriptor leaves the lock held until the
child exits. This supports descriptor inheritance as the cause of the intermittent
failure. Context7 was out of quota, so the investigation used the
[Rust File reference](https://doc.rust-lang.org/std/fs/struct.File.html#method.lock)
and [Linux flock reference](https://man7.org/linux/man-pages/man2/flock.2.html).

The existing check now runs alone in a child test process. It still requires the
lock during staging, publication, and finish. It still requires immediate lock
acquisition after publication drops. The parent requires exactly one passing
child test. No assertion was deleted, and no retry or sleep was added.

The repaired Linux library suite passed 30 runs with 32 parallel threads.
The full Linux and local macOS workspace suites passed. Local Clippy passed
with warnings denied. A descriptor-leak mutation in an isolated source copy
compiled and failed the retained post-drop assertion. It exited with status 101.
The candidate source was restored byte for byte after the mutation.

## Limits

The local derivations test actual CLI, Nix, process, and filesystem behavior.
They do not test vendor downloads, a clean-host pkg installation, reboot,
Gatekeeper, or every tap and catalog path. Linux does not prove macOS behavior.
The macOS run includes the existing cask bounds and real app helper journey.
CI retains native command results and cancellation logs for seven days.

TraceDecay served the indexed main ancestor. Its dependent-file result for
`commands/change.rs` named `commands/lifecycle.rs` and reported partial coverage.
Direct source reads and native execution supplied the subprocess evidence.
The graph result is not executed coverage.
